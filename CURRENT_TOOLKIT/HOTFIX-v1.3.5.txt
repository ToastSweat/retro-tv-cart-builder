RETRO TV CART BUILDER v1.3.5
==============================

INVALID MANUAL REPLACEMENT FALLBACK
-----------------------------------
A replacement selected in the browser can become invalid by the time the review
is applied.

The exact NICK01 case that exposed this:
- NICK01-BREAK-04-IN selected BR-85daaac2f1f8 as its replacement.
- That same BR-85daaac2f1f8 asset appears later in the cart at BREAK-11-IN.
- BREAK-11-IN was marked BAD_AUDIO in the same review.
- Apply-RetroCartReview correctly changed that source's global status from READY
  to BAD_AUDIO before replacement validation.
- The old script then tried to use the now-non-READY asset as a replacement and
  stopped.

v1.3.5 fixes this.

When -AutoReplace is supplied:
- manually selected replacement IDs are validated first;
- if the selected asset is missing, non-READY, incompatible, already used, busy,
  or is literally the same asset being replaced, the script prints a warning;
- it clears that invalid choice and automatically finds another compatible READY
  replacement instead of aborting.

Without -AutoReplace, invalid manual choices remain an unresolved review item so
the script still never silently changes the user's requested replacement.

Also fixed:
AutoReplace can no longer choose the same asset that is currently being replaced.

No review CSV edits are required for NICK01 r004. Rerun the same apply command.
The previous failed run did not advance the cart registry to r005; source-health
flags written before the failure are valid review findings and are safe to write
again.
